# ربط النموذج بقاعدة بيانات Supabase

نموذج البريف (`/brief`) ولوحة الطلبات (`/admin`) يرسلان/يقرآن من مشروع Supabase.
المشروع القديم توقّف، لذا اتبع هذه الخطوات لربط مشروع جديد.

## الخطوات (٥ دقائق)

1. **أنشئ مشروعًا** على <https://supabase.com> (الباقة المجانية تكفي).

2. **أنشئ الجدول والصلاحيات:** افتح **SQL Editor** في مشروعك، والصق محتوى
   [`setup.sql`](./setup.sql) ثم اضغط **Run**.

3. **انسخ المفاتيح** من **Project Settings → API**:
   - `Project URL` → مثل `https://abcd1234.supabase.co`
   - `anon public` key

4. **اضبط متغيّرات البيئة:**

   **محليًا** — أنشئ ملف `.env.local` في جذر المشروع (انظر `.env.example`):
   ```
   NEXT_PUBLIC_SUPABASE_URL=https://abcd1234.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...المفتاح
   ```

   **على Vercel** — Project → **Settings → Environment Variables**، أضف نفس
   المتغيّرين، ثم **أعد النشر (Redeploy)** حتى تُضمّن القيم في البناء.

5. **جرّب:** افتح `/brief`، أرسل طلبًا تجريبيًا، وتحقّق من ظهوره في `/admin`
   وفي **Table Editor → requests** داخل Supabase.

## ملاحظات

- المفتاح `anon` عام بطبيعته وآمن للاستخدام في الواجهة، لكننا لا نثبّته في
  الكود لتسهيل التبديل والتدوير.
- لوحة `/admin` تقرأ بمفتاح anon، ما يعني نظريًا أن من يملك المفتاح قد يقرأ
  الطلبات. لحماية أقوى لاحقًا: انقل القراءة إلى مسار خادمي بمفتاح `service_role`
  واحذف سياسة القراءة العامة من `setup.sql`. (كلمة مرور اللوحة أيضًا مثبّتة في
  الكود حاليًا — يُفضّل نقلها إلى متغيّر بيئة.)
